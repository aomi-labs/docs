---
title: "Errors and retries"
description: "Handle Agent, Pipeline, schema, authorization, and retryable failures in TypeScript integrations."
---

The client exposes typed errors for the failure classes an integration normally needs to handle.

```ts
import {
  AgentApiError,
  PipelineApiError,
  PipelineSchemaError,
} from "@aomi-labs/client";
```

## Handle API errors

```ts
try {
  await aomi.agent.run("Check my positions.");
} catch (error) {
  if (error instanceof AgentApiError) {
    console.error(error.code, error.requestId);

    if (error.retryable) {
      scheduleRetry();
    }
  }
}
```

`AgentApiError` and `PipelineApiError` expose:

| Property | Description |
| --- | --- |
| `status` | HTTP status code. |
| `code` | Stable machine-readable error code. |
| `retryable` | Whether the failure is normally safe to retry. |
| `requestId` | Identifier to include in support or server-log searches. |
| `details` | Optional structured context. Do not assume one shape for every code. |

## Handle schema errors

`PipelineSchemaError` is local. It means the supplied arguments do not match the live operation schema.

```ts
try {
  await aomi.pipeline
    .app(selectedApp)
    .build(selectedOperation, formValues);
} catch (error) {
  if (error instanceof PipelineSchemaError) {
    showFieldErrors(error);
  }
}
```

Refresh the operation descriptor before retrying. The live catalog can change independently of your application release.

## Retry safely

- Retry only when `retryable` is true or the endpoint reference explicitly permits it.
- Reuse the same idempotency key when retrying one logical mutation.
- Respect `Retry-After` when the service returns it.
- Keep Agent progress cursors opaque. If a cursor expires, fetch from the beginning and reconcile by event ID.
- Never retry a wallet signature prompt without showing the user the exact current request again.

## Authentication failures

| Status | First check |
| --- | --- |
| `401` | The guest session or access token is missing, expired, or invalid. |
| `403` | The token has the wrong resource audience or lacks the required scope. |
| `409` | An idempotency key was reused with different input, or a Build became stale. |
| `429` | The caller reached an environment or account limit. |

See [Authentication](/integrate/authentication) for the supported identity paths.

---
title: "Agent API"
description: "Use the Agent REST API for stateful turns, progress cursors, interruption, actions, and session management."
---

The Agent API owns conversation state. Start a turn, reduce the returned ordered events, and continue from the opaque cursor until a `turn_state_changed` event is terminal or needs user input.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/agent/chat` | Start a turn. |
| `GET` | `/v1/agent/chat/{sessionId}` | Read new progress and messages. |
| `POST` | `/v1/agent/chat/{sessionId}/interrupt` | Interrupt active work. |
| `POST` | `/v1/agent/chat/{sessionId}/actions/{actionId}/result` | Resolve or reject an action. |
| `GET` | `/v1/agent/sessions` | List sessions with cursor pagination. |
| `GET` | `/v1/agent/sessions/{sessionId}` | Read one session. |
| `PATCH` | `/v1/agent/sessions/{sessionId}` | Rename or archive a session. |
| `DELETE` | `/v1/agent/sessions/{sessionId}` | Delete a session. |

## Start a turn

```bash
curl -X POST "$AOMI_BASE_URL/v1/agent/chat" \
  -H "Authorization: Bearer $AOMI_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: turn-8b5f" \
  -d '{"sessionId":"demo-session-8b5f","message":"Explain my USDC balance on Base"}'
```

The response is an event page:

```json
{
  "session_id": "demo-session-8b5f",
  "cursor": "opaque-cursor",
  "events": [],
  "has_more": true
}
```

Messages, tool activity, actions, errors, and lifecycle changes are entries in `events`; they are not separate top-level response fields.

## Check progress

```bash
curl "$AOMI_BASE_URL/v1/agent/chat/$SESSION_ID?cursor=$CURSOR&wait=30000" \
  -H "Authorization: Bearer $AOMI_AGENT_TOKEN"
```

`wait` is bounded to 30 seconds. Apply events in sequence order and repeat while `has_more` is true or the latest turn state is `processing`. Stop at `complete`, `failed`, `interrupted`, or `awaiting_action`.

Keep the cursor opaque. An expired cursor returns `410`; request the session without a cursor and reconcile the returned event page.

## Manage sessions

```bash
curl "$AOMI_BASE_URL/v1/agent/sessions?limit=20" \
  -H "Authorization: Bearer $AOMI_AGENT_TOKEN"
```

Session ownership comes from the authenticated caller. Do not use a wallet address as an ownership key.

## Submit an action result

Action resolution requires its own permission and an idempotency key. Submit only the result produced by the reviewed request. Never replace the action payload with caller-authored transaction fields.

The action result body includes the action `revision` and the typed `result`. Guest access on staging does not include `agent:actions:resolve`.

For TypeScript integrations, use [Agent SDK](/integrate/typescript/agent) so action types and progress polling remain synchronized with the released client.

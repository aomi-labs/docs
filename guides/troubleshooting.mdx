## CLI Issues

**`aomi: command not found`**
Install `@aomi-labs/cli` globally and ensure the npm global bin directory is in your PATH.

**Stale session state**
Clear `~/.aomi/` to reset all local session state.

## Execution Issues

**Simulation fails**
- Verify the target chain is supported
- Check RPC endpoint availability
- Ensure the wallet has sufficient funds for gas (even on fork)

**Transaction not executing**
- Check that the wallet is connected and has the correct network selected
- Verify the API key has permission for the requested App
- Review simulation output for errors

## UI Integration

**Widget not rendering**
- Confirm React 18 or 19; mount the widget from a client component in Next.js.
- Import `@aomi-labs/widget/styles.css` and pass your activated App's `applicationId`.
- The default API is `https://chat.aomi.dev`; use an explicit absolute `apiUrl` for another deployment.
- Browser wallets work by default. If you selected Para or Privy, install that provider and pass its public configuration explicitly.

See [widget troubleshooting](/guides/widget/troubleshooting) for origin and wallet checks. The package does not require shadcn initialization or read Next.js environment variables.

**Widget vs Headless**
- Use the widget for quick integration with standard chat UI
- Use the headless library for fully custom designs
- Both share the same backend, so you can switch between them without server changes

## API Issues

**401 Unauthorized**
The caller credential is missing, expired, or bound to another resource. Sign in again or obtain a grant for the exact Agent, Pipeline, or MCP resource. An App selector is not a credential. See [Authentication](/api-reference/authentication).

**403 Forbidden**
Check the error code first:

- `insufficient_scope`: the credential lacks a scope or targets another resource. A guest cannot perform this operation in this environment; sign in with [OAuth](/integrate/authentication#oauth-for-a-service-or-cli) and request the exact resource.
- A `403` when you call a **private** App: the `Aomi-App-Key` header carries a key that is not scoped to that App. Newer backends return `app_key_not_scoped`. Use a key created for that App. A missing key returns `401` (`app_key_required` on newer backends).

Default and public Apps never need an App key. See [Which credential do I need?](/integrate/authentication#which-credential-do-i-need).

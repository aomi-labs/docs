---
title: "Installation"
description: "Install the widget and optionally add a Para or Privy wallet."
---

You need React 18 or 19 and an activated public App with its Application ID.
Production hosts require HTTPS; HTTP is accepted only on loopback hosts. In Next.js, mount the widget from a
client component. The widget
includes its compiled styles; Tailwind and the shadcn CLI are not required.

```bash
npm install @aomi-labs/widget
```

The [quickstart](/guides/widget/quickstart) uses browser wallets by default.
Choose an embedded wallet only when your product needs that sign-in experience.
Install only the provider you use. The `auth` prop loads that provider's SDK on
demand; there is no provider module to import. Browser-wallet and guest chat do
not require either SDK.

These examples target `@aomi-labs/widget` 3.1.0. Use them after that release is
published; check your installed package version before adopting them. The
deprecated `@aomi-labs/widget-lib` name remains compatible through 4.x and will
be removed in 5.0.

The package does not read framework environment variables. Your host can read
public values with `process.env.NEXT_PUBLIC_*` in Next.js or
`import.meta.env.VITE_*` in Vite and pass them to `baseUrl`, `applicationId`, or
the selected auth factory. Provider secrets stay on your server.

## Privy

```bash
npm install @privy-io/react-auth@2.25.0 @privy-io/wagmi@1.0.6 \
  @solana/kit@^2.3.0 @solana/spl-token@^0.4.9 \
  @solana-program/token@^0.5.1 @solana-program/system@^0.7.0 \
  permissionless@^0.2.47 @abstract-foundation/agw-client@^1.0.0
```

```tsx
"use client";
import { AomiWidget, privyAuth } from "@aomi-labs/widget";
import "@aomi-labs/widget/styles.css";
export default function Assistant() {
  return <AomiWidget applicationId="123" auth={privyAuth({ appId: "YOUR_PUBLIC_PRIVY_APP_ID" })} />;
}
```

Privy imports its Solana and smart-wallet feature peers during bundling, so include
them even when your host uses only basic wallets. The widget accepts Privy React
2.x and its wagmi adapter 1.x; the versions above are the installation recipe
for these examples.

## Para

```bash
npm install @getpara/react-sdk@2.19.0 @getpara/wagmi-v2-connector@2.19.0
```

```tsx
"use client";
import { AomiWidget, paraAuth } from "@aomi-labs/widget";
import "@aomi-labs/widget/styles.css";
export default function Assistant() {
  return <AomiWidget applicationId="123" auth={paraAuth({ apiKey: "YOUR_PUBLIC_PARA_PROJECT_KEY" })} />;
}
```

The widget requires both Para packages at 2.19.0. `environment` defaults to
`"PROD"`; pass `"BETA"` for a Para beta key. If the selected provider's package
is missing, the widget shows which package to install instead of failing the page.

Pass public provider identifiers explicitly. Your host may load them from its
own configuration, but the widget does not read environment variables. Allow
your host origin in the provider's project settings when required. Never pass
an App secret, provider secret or private key to browser code.

SDK loading and provider changes preserve the chat and composer draft. If your
host presents provider choices, `preloadWalletProvider("privy" | "para")` warms
the installed SDK on hover or focus without changing the selected account.
Composed hosts can offer providers through `WalletSignInOptionsContext` from
`@aomi-labs/widget/host-composition`. The wallet kit warms those SDKs and opens
the chosen login once its runtime is ready. A loaded provider stays mounted
when you choose another provider; only the active provider supplies the wallet
runtime. Changing providers does not sign out of your Aomi account.

## Existing integrations

`@aomi-labs/widget-lib` remains a compatibility package. It retains the
previously bundled Para and Privy dependencies and eager provider registration.
The canonical package's legacy `auth.kind` objects, `apiUrl` prop, main-entry
composition exports and compatibility component subpaths are deprecated and
removed in 4.0. The old package name has the separate 5.0 removal window above.
Use `@aomi-labs/widget`, `privyAuth`, `paraAuth`
and `baseUrl` for new integrations. Hosts that compose `AomiFrame` themselves
import it from `@aomi-labs/widget/frame` and the wallet kit and account UI from
`@aomi-labs/widget/host-composition`. Registry copy-in installs are
retired; existing registry JSON remains frozen during its announced retention
window.

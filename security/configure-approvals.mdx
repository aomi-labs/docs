title: "Configure approvals"
description: "Choose Ask me, Auto, or Locked per wallet in Safety, and configure provider-delegated automatic signing separately."
---

Each linked wallet has its own signing policy. Open **Settings → Safety** to
choose how it signs. Manage connections and linked sign-in methods under
**Settings → Account → Wallets & access**.

Read [Signing](/security/signing) for what happens when a transaction needs a
signature. These controls are separate from the transaction safety level for
your chats.

<Tip>
Start with **Ask me**. Enable an automatic path only after you understand
which wallet will sign and how to stop it.
</Tip>

## Find the signing controls

<Steps>
  <Step title="Open Settings">
    Open **Settings** in the Aomi portal and select **Safety**.
  </Step>
  <Step title="Find Signing">
    Each row shows the wallet name, shortened address, chain family, and
    **Ask me**, **Auto**, and **Locked** choices.
  </Step>
  <Step title="Match the wallet">
    Check the address and chain family before changing a choice. EVM and Solana
    wallets have separate policies. A choice the wallet cannot support stays
    visible but disabled.
  </Step>
</Steps>

## Ask me

Choose **Ask me** to approve each transaction in your wallet. Aomi prepares the
transaction, then waits for your approval. Rejecting the request produces no
signature and does not change your signing policy.

This is the starting policy for a newly linked user-controlled wallet.

## Auto

Choose **Auto** to let a compatible Privy or Para wallet client sign without a
separate prompt for each transaction. The signing client must be available.
Aomi does not receive its private key or substitute a different wallet if the
client is unavailable.

This choice is disabled for external browser wallets. It is different from the
provider-delegated **Automatic signing** section below.

## Locked

Choose **Locked** to prevent this wallet from signing through Aomi. It stays
linked to the account, and its funds and keys remain where they are.

## Change a signing policy

Changing a choice prepares an authorization; it does not commit the change
immediately.

1. Select the new choice for the correct wallet.
2. Review **Confirm signing policy**, including the address, old and new
   choices, and **Payload to sign**.
3. Click **Sign to approve** and review the wallet request.
4. Wait for the saved choice to appear in the row.

Loosening a policy requires the target wallet's signature. A qualifying wallet
on the same account can authorize a tighter policy. If you reject the request,
the policy stays unchanged. If its version changes in another session or the
request expires, start again from the current state.

## Provider-delegated automatic signing

The separate **Automatic signing** section is for eligible provider wallets
that can sign while this browser is closed. It needs both a wallet policy that
allows this path and a live delegation for that exact wallet.

Logging in through Privy or Para does not enable it. Setting **Auto** in a
Signing row does not create a provider delegation.

### Privy

<Steps>
  <Step title="Connect an eligible Privy wallet">
    Open a chat thread and ensure the intended Privy wallet is available.
    In **Settings → Safety**, find **Automatic signing**.
  </Step>
  <Step title="Enable the provider delegation">
    Where offered, click **Enable** next to **Enable automatic signing**.
    Privy asks once to add Aomi as a delegated requester. Approve only if you
    want this capability.
  </Step>
  <Step title="Set up the specific wallet">
    Click **Set up** for the eligible wallet. Review and sign the policy
    authorization. The delegation alone does not change every wallet's policy.
  </Step>
  <Step title="Review the result">
    The wallet shows its delegation status and a **Manage** control when
    automatic signing is enabled. An expired or revoked delegation blocks
    signing until renewed.
  </Step>
</Steps>

### Para

Para uses a separate provider-managed agent wallet for unattended work.
Your user-controlled login wallet remains separate.

<Steps>
  <Step title="Sign in with Para">
    Link the Para login wallet to your Aomi account.
  </Step>
  <Step title="Create the agent wallet">
    In **Settings → Safety → Automatic signing**, find
    **Enable automatic signing on Ethereum** or
    **Enable automatic signing on Solana**, where offered. Click
    **Create agent wallet** for the intended chain family.
  </Step>
  <Step title="Check the new address">
    The agent wallet is a different address. Fund only the assets and gas
    required for its intended work.
  </Step>
  <Step title="Set up signing when offered">
    Use **Set up** on the agent-wallet row to review and authorize its signing
    policy. Check its delegation status before relying on unattended execution.
  </Step>
</Steps>

<Warning>
A Para agent wallet has its own address and balances. Creating it does not
transfer funds from your login wallet or automatically authorize that login
wallet to sign unattended.
</Warning>

## Stop or renew automatic signing

| Goal | Action |
| --- | --- |
| Require transaction prompts again | Choose **Ask me** for a user-controlled wallet |
| Prevent a user-controlled wallet from signing | Choose **Locked** |
| Disable a provider-delegated signing policy | Open **Manage** and select **Turn off** |
| Revoke one live provider grant | Open **Manage** and select **Revoke delegation** |
| Revoke every provider grant | Click **Revoke all** beside **Stop all auto-signing** |
| Restore an unavailable delegation | Click **Renew** for that wallet and complete the required setup |

**Turn off** returns a user-controlled wallet to **Ask me** and locks a
provider-managed agent wallet. Revoking a delegation and changing a policy
are separate actions. Either missing gate prevents provider-delegated signing.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| **Auto** is disabled in Signing | That wallet does not support the client signing mode. External wallets use **Ask me** or **Locked**. |
| **Not enabled** under Automatic signing | Complete the eligible provider setup; connecting alone does not create a delegation. |
| **Renew** | Renew the wallet's provider delegation. A saved automatic policy cannot bypass an expired grant. |
| The policy authorization fails or expires | Review the current wallet and policy, then start a fresh request. |
| The wallet is unavailable | Reconnect or select the exact wallet under **Account → Wallets & access**. |
